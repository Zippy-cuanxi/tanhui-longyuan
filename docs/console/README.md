# 碳惠陇原后台管理系统（一期）实现说明

> 本文档对应本次「管理员端 + 商家端」交付。后台与消费者商城在同一个 Vue 3 / Vite 工程内，商品、订单、结算等数据层当前使用本地 mock，页面只通过 `src/console/api` 访问数据，后续可替换为真实接口。

## 1. 启动与构建

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm run typecheck
npm run lint
npm run format:check
npm run build
```

- 后台入口：`/console/login`
- 商家端：`/console/merchant/...`
- 管理员端：`/console/admin/...`
- 消费者商城原有入口（`/`、`/products`、`/cart` 等）未改动。
- Element Plus、ECharts、Element Plus 图标只在首次进入 `/console` 时加载，不进入消费者首屏；离开后台时会移除 `body.console-mode`。

## 3. 目录结构

```
src/console/
  api/            # 页面唯一数据访问层：auth / merchant / admin / common / types
  components/     # 列表、详情抽屉、状态页签、空态、错误态、权限门、图表等
  composables/    # 1280 宽度下的表格列压缩
  constants/      # 菜单、状态字典、角色权限
  layouts/        # ConsoleLayout（侧栏 + 顶栏）
  mock/           # 本地 mock DB 与确定性种子数据
  router/         # /console 路由、路由守卫、RouteMeta 类型
  stores/         # console-auth / console-app
  styles/         # 后台独立主题（body.console-mode）
  utils/          # 格式化、CSV、错误适配
  views/
    merchant/     # 商家端页面
    admin/        # 管理员端页面
```

静态资源：`public/console-assets/icons`、`public/console-assets/images`。设计参考图：`design/console/`。规格文档：`docs/console/碳惠陇原-后台管理系统设计方案.md`、`docs/admin-console-spec.md`。

## 5. Mock 数据与闭环

- localStorage key：`tanhui_console_db_v1`（当前种子版本 3）。
- 所有 mock API 延迟 300–600ms；顶栏「仿真环境」面板可开启约 10% 随机失败，便于验证错误态/重试。
- 顶栏 Mock 面板支持重置数据（恢复初始种子）。
- 种子规模：24 商家、24 店铺、28 商品、36 订单、24 售后、32 结算单、28 提现、30 会员、8 分类、20 公告、5 管理员、40 操作日志、24 通知；订单覆盖全部状态，且含当日订单。
- 六个闭环均已实现并通过浏览器联调：
  1. 商家入驻审核通过 → 商家状态/登录页 → 正常进入工作台。
  2. 商品提交审核 → 管理员通过/驳回 → 商家商品状态更新；仅修改价格/库存不触发审核。
  3. 待发货订单填写快递公司/单号 → 订单变为待收货；发货时效展示剩余/超时红色。
  4. 商家拒绝售后（必填原因）→ 进入平台仲裁 → 管理员支持/驳回退款 → 订单状态与待结算扣减更新。
  5. 商家申请提现 → 管理员通过/驳回 → 商家余额冻结/可用与提现记录更新。
  6. 入驻审核、冻结/解冻、售后仲裁、提现审核、角色权限、佣金/基础设置等高风险操作写入操作日志，管理端可按模块/风险/日期查询。

## 6. 权限与路由

- 路由集中在 `src/console/router/index.ts`，前缀 `/console`，全部懒加载。
- 路由 meta：`consoleAuth`、`consolePublic`、`consoleRole`、`permission`、`anyPermissions`、`bare`、`title`、`group`。
- 菜单集中在 `src/console/constants/menu.ts`，按角色权限过滤；同路径不同 tab 的「系统设置/操作日志」做了互斥高亮。
- 权限码与角色映射在 `src/console/constants/permissions.ts`；按钮级权限通过 `auth.can` / `ConsolePermissionGate` 控制。
- 无权限访问 → `/console/forbidden`；商家非正常状态 → 账号状态页；未登录/过期 → 登录页并带 `redirect`。
- 1280px 下财务/订单等列较多的表格自动隐藏次要列（明细仍在详情抽屉/完整字段），避免 1280 出现横向滚动；<1280 页面允许横向滚动，但 `.console-shell` 最小宽度 1280 不破版。

## 7. 状态字典

集中在 `src/console/constants/labels.ts`：商家、商品、订单、售后、结算、提现、公告、会员、店铺、风险等状态的颜色、文案和背景色统一维护，页面不再写死状态中文。金额使用字符串 + `formatMoney`，避免浮点误差。

## 8. 后续替换真实接口

1. 保持 `src/console/api/types.ts` 的 DTO/ViewModel 类型，或按后端 DTO 做适配。
2. 逐个替换 `src/console/api/auth.ts`、`merchant.ts`、`admin.ts`、`common.ts` 中函数的实现；页面不直接访问 `mock/db`。
3. 建议接口前缀：`/api/v1/console/...`，登录返回 `ConsoleSession`（token、role、account、permissions、status）；商家端与管理员端可用不同 token 类型。
4. 列表统一接收 `page`、`page_size`、`status`、`keyword`、`storeId`、`date_from`、`date_to`，返回 `{ items, pagination }`。
5. 高风险接口（审核/冻结/仲裁/提现/权限/设置）由后端写操作日志，前端仍保留确认弹窗与原因必填。
6. 文件上传：商品图片、营业执照、资质材料当前为本地素材选择；接真实接口时替换为上传服务返回的 URL。
7. 错误规范：后端返回非 2xx 时，建议提供 `code`、`message`、`request_id`，前端错误态会展示并支持重试/复制 request_id。
8. 移除 mock 后端后可删除 `src/console/mock/`，但保留 `MockApiError` 的错误结构或迁移到统一 HTTP 客户端。

## 9. 设计与规格冲突 / 假设

- **应用形态**：规格方案建议独立 `tanhui-admin` 应用、真实 API、`/admin` 路径；本次按用户要求改为现有工程内 `/console`，管理员端 + 商家端共用一套懒加载后台，数据使用 mock。
- **设计图缺失**：源素材仅提供 `00` 设计规范板和 `01a` 登录页；`02–16` 页面设计图与 `assets/console/manifest.md` 未提供。本次按 00 的色板/间距/圆角、01a 的登录分栏，以及规格文档的业务结构实现；其余页面为规范化推导，已在交付说明中标注。
- **侧栏风格**：规格提到深绿色侧栏，00 规范板为浅色侧栏 + 绿色选中态；按设计稿实现浅色侧栏。
- **表格行高**：用户要求 48px，规格为 44px；按用户要求基础行高 48px，含商品缩略图/双行信息时保持紧凑自适应。
- **用户管理**：用户要求只读列表 + 详情，本期未提供封禁按钮；权限码中保留 `user:ban` 供后续接入。
- **管理员审核权限**：`merchant:review` 默认只授予超级管理员；运营管理员只能查看商家。若业务需要运营审核，可在角色权限页开启。
- **产地数据**：直接复用消费者端 `src/mocks/mock-origin-heat.json` 的 7 个产地；管理端编辑只更新本地 DB 中的展示标签/商品数，不会改写消费者端静态 JSON。
- **金额/物流/支付/上传**：均为演示数据；不产生真实支付、物流、短信、上传或退款。
- **二期功能**：菜单保留并统一跳 coming-soon 插图页；不实现二级功能本身。

## 11. 已知限制

- 无真实后端、对象存储、支付、物流轨迹、短信/邮件服务。
- 评价、绿色积分、二级子账号、Banner 等按二期处理。
- 管理端暂无独立「通知中心」，顶栏消息使用操作日志/业务通知 mock。
- 商品审核时间使用最近更新时间（`updatedAt`）展示；真实后端建议返回独立 `submitted_at`。
- 商家端与管理端共用本地 mock DB；跨浏览器/跨设备不同步。
- 1280 下财务/订单表格隐藏部分次要列；完整字段可在详情抽屉或导出中查看。
