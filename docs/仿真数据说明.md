# 碳惠陇原 · 仿真测试数据说明

> 本轮为测试准备了一批覆盖**全业务状态**的仿真数据，直接写入后端真实 SQLite，
> 因此消费者端（5174）与管理端（4174）都能看到，最贴近真实联调。
> 所有仿真实体以 `SIM` 标记，与 seed 基础数据隔离，可反复重置。

## 1. 生成与重置

```bash
# 生成/重置仿真数据（幂等：重复运行会先清掉旧 SIM 数据再重建，不会累积）
npm run sim:data

# 验证仿真数据在两端 UI 可见（10/10 通过）
npm run sim:verify
```

- 生成脚本：`scripts/generate_sim_data.py`（用后端自身 Argon2 算法生成密码哈希、UUID 主键、字段严格按模型 schema）
- 验证脚本：`scripts/verify-sim-data.mjs`
- 生成前已单独备份数据库：`tanhui_dev.db.bak-simdata-20261124_163333`
- 上一轮流程测试遗留的 2 家"流程验证合作社"及其关联数据已清理，库回到干净起点。

## 4. 建议测试路径

1. **登录与权限**：用上表各角色账号登录，确认菜单与数据范围正确。
2. **商家入驻审核**：管理端 → 商家管理 → 入驻审核，对 2 个 `SIM-` 待审商家执行通过/驳回。
3. **商品审核与上架**：商家端对草稿/驳回商品提交审核 → 管理端商品审核通过 → 商家端上架 → 消费者端 `SIM-在售` 商品可见。
4. **订单履约**：管理端订单列表按状态页签筛选 → 对待发货单发货 → 消费者端物流页查看单号。
5. **售后仲裁**：管理端售后列表对 `SIM-RF` 待处理单裁决 → 消费者端退款记录变化。
6. **内容运营**：管理端发布 `SIM-` 草稿公告 → 消费者公告页可见；下线后消失。

## 5. 注意事项

- 仿真数据与 seed 基础数据**共存**（基础 2 商家/7 商品仍保留），统计总数为：
  users 11 / merchants 7 / stores 4 / products 17 / orders 7 / refunds 3 / announcements 4。
- 消费者端商品列表只返回 `approved && is_listed` 的商品，因此 10 个 SIM 商品中只有 3 个"在售"可见，这是审批闸门的正确行为，不是数据缺失。
- 重置仿真数据请用 `npm run sim:data`，不要直接改库——脚本保证外键关联完整与幂等。
- 后端实际运行库在桌面 `碳惠陇原统一后端-tanhui-backend`；项目内 `tanhui-backend` 为同源代码副本。
